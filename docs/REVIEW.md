# Объективный разбор Bananabun

Дата: 28 октября 2026. Основа: исходная папка «проект х», файл `Bananabun Progress.html`, статическая проверка, локальная PostgreSQL, браузерные тесты и отдельные проверки действующих подключений.

## Главный вывод

Claude оставил существенную основу работающей платформы, а не пустой макет. Однако утверждение «готово на 95%» измеряло ручные отметки в HTML, а не готовность к эксплуатации. На момент анализа в HTML было 142 пункта: 130 `done`, 9 `partial`, 3 `todo`. Формула считала `partial` за половину готового пункта и округляла результат до 95%.

В исходниках были ошибки и в разделах, отмеченных готовыми. Первому полноценному заливу также мешали внешние условия: неработающий доступ FA, отсутствие Cloudflare Access и необходимость выбрать реальные параметры рекламы. Эти вещи нельзя честно закрыть одной галочкой «код написан».

## Что в работе Claude было сделано разумно

- Разделены интерфейс, API и агент на Mac. Работа с Facebook проходит через профиль AdsPower, а не напрямую с IP сервера.
- У ключа агента в базе хранится хеш. Передача профилей ограничена выбранными полями; исходные пароли и прокси не должны попадать на сервер.
- У обычных защищённых маршрутов текущие роль и команда уже перечитывались из базы. Ошибка заключалась в обходе этого механизма отдельной административной группой.
- Создание рекламы предусматривало PAUSED, явные бюджет и ставку, сохранение состояния и продолжение после ошибки.
- В сборщике лендингов уже было экранирование большинства товарных данных и устранение выдуманного рейтинга.
- В обновлении списка Facebook предусмотрено сохранение старого снимка кабинета при ошибке чтения.

Это хорошая основа. Главный недостаток — недостаточная проверка сквозных сценариев и слишком уверенные отметки о завершении.

Обновлены Fastify и его плагины, сборщик и маршрутизация. Для паролей используется совместимая с существующими bcrypt-хешами библиотека без нативной сборки. Проверены работа API и сборка после обновления.

## Проверки и пределы доказательств

- 26 автоматические проверки прошли без пропусков при запуске с отдельной PostgreSQL и Chromium.
- Проверены права и отзыв токенов, область видимости, расчёты, миграции, откат активов, повтор запроса, восстановление зависаний, компиляция характеристик и создание изображений.
- FA MCP проверен на имитированных ответах: подключение, подтверждение черновика, область команды и запрет отправки ключей постороннему origin. Это не живой платный скрап.
- Создание Facebook-объектов проверено через заменённый транспорт: одна кампания, три адсета, отдельные ставки, шесть объявлений из двух креативов, PAUSED и продолжение после ошибки. На живом Facebook эти операции не выполнялись.
- Сборка интерфейса прошла. Проверены вход на компьютере и телефоне, переход после входа и девять разделов на тестовых данных без необработанных ошибок браузера.
- Реальная проверка AdsPower подтвердила 11 профилей. Открытых профилей в момент проверки было 0.
- Реальный запрос подключения FA с уже настроенным на VPS токеном получил 401. Оба параметра Cloudflare Access в окружении отсутствовали.
- Рабочая реклама, рабочая база и настройки VPS не изменялись; новая версия на VPS не выкатывалась.

Сохранение локального состояния уменьшает риск дублей, но не обеспечивает математическое exactly-once: если Facebook создал объект, а ответ потерялся до сохранения ID, нужна сверка с кабинетом. Такой живой отказ не проверен и не должен объявляться полностью решённым.
