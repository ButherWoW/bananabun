# Собственные креативы: параметры и устойчивая очередь

Ветка `chatgpt-own-creatives`. FA и внешний AI для этой сборки не используются.

## Результат

- Поле «Надпись на креативе» помещает введённый текст на изображение. Это буквальная надпись, а не генерация композиции по запросу. До 200 символов.
- Загруженный логотип отображается в макете; сохранённый логотип из пресета передаётся при следующей сборке. Ошибка загрузки видна пользователю и не запускает сборку без логотипа.
- «Разные стили» действительно выбирает разные оформления; без него используется один стиль. После пяти стилей оформления повторяются. Референсы — исходные картинки, не анализ композиции.
- Неиспользуемый выбор лендинга убран из формы. Неподтверждённая фраза о быстрой доставке и безусловная метка распродажи убраны из рендера.
- Реальное фото обязательно. Локальные файлы читаются только из uploads, проверяются путь и тип, внешние URL не скачиваются рендером. Разметка в названии, характеристиках и надписи экранируется. Chromium работает без скриптов страницы и сетевых запросов.

## Очередь

Миграция `022_creative_queue.sql` добавляет попытки, время начала и идентификатор обработчика. Создание партии выполняется одним SQL-запросом: частичной партии после ошибки вставки нет. Параметры сохраняются в metadata.options до начала обработки.

Задание сначала pending, затем processing, done или failed. Обработчик запускается вместе с backend. После прерывания processing-задание можно забрать через пять минут; после трёх прерванных попыток оно становится failed с причиной. Повтор вручную ставит ту же запись в очередь и сохраняет её параметры. Два обработчика используют блокировку строк и не берут одну запись одновременно. Устаревший обработчик не может записать результат поверх нового идентификатора обработки.

Старые незавершённые FA-записи помечаются ошибкой с предложением собственной сборки; готовые файлы не удаляются. Готовые локальные результаты не перерендериваются при перезапуске. Если обработчик потерял право на запись результата, его новый файл может остаться без записи в БД; автоматическая уборка таких файлов в этой доработке не добавлена.

Это устойчивая очередь картинок, не гарантия exactly-once для рекламы. Никакие рекламные объекты в этих проверках не создаются.

Миграция `024_auto_creative_batch.sql` добавляет защиту автоматических партий: внутренний ключ события скрапа и номер картинки уникальны для товара. `generateFromScrapePreset(productId, { batchKey })` передаёт ключ из обработчика скрапа. Одновременное восстановление и повтор после вставки не создают дополнительные записи. Внешний запрос API не может задать этот внутренний ключ; ручная генерация остаётся отдельным намеренным действием. Восстановление самого события между завершением скрапа и постановкой партии выполняет обработчик Claude (миграция 023).

## Проверки

```sh
node --test platform/backend/test/standalone.test.js platform/backend/test/creative-assets.test.js
BANANABUN_TEST_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:PORT/buyer_access_test node --test platform/backend/test/creative-queue.test.js
BANANABUN_TEST_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:PORT/buyer_access_test RUN_BROWSER_TESTS=1 node --test platform/backend/test/startup.test.js
node platform/backend/test/standalone-browser.mjs
npm run build --prefix platform/frontend
node platform/frontend/test/standalone-smoke.mjs
```

База только локальная, имя заканчивается на `_test`. Тесты создают отдельные схемы и удаляют только их. Chromium должен быть установлен через Playwright. Полный startup-тест с RUN_BROWSER_TESTS проходит вход, загрузку логотипа, постановку в очередь и настоящий рендер отдельным процессом сервера. Браузерный тест отдельно проверяет размеры и изменение пикселей после надписи/логотипа. UI-тест работает на фикстурах API.

## Передача Claude

Для совместного этапа восстановления автогенерации также нужны миграции 023 и 024 до перезапуска.

Сначала миграция 022, затем перезапуск backend и пересборка интерфейса. Новую очередь запускает index.js; изменения его lifecycle нужно сохранить при объединении. HOST можно задать для локальной проверки; поведение существующего сервера по умолчанию сохранено. Обновление агента для этой доработки не требуется.

До выкатки объединить с текущим main и повторить проверки. Живые Amazon, FB и Keitaro для этой доработки не вызывались; выкатывает Claude по правилам AGENTS.md.
