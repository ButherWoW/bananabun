# Передача Claude: Bananabun полностью без FA

Актуализация: собственные креативы, права, восстановление и новая установка проверены; ниже сохранён исходный разбор. Итоги нового этапа: [BOOTSTRAP_CHECKS.md](BOOTSTRAP_CHECKS.md), 49 тестов, включая Walmart Claude, и полный локальный Docker-прогон. Свежие lock-файлы проверены онлайн, известных уязвимостей npm не найдено. Статус выкатки — в общем HANDOFF.md.

Требование владельца: **весь рабочий сценарий строим сами, FA не подключаем**. FA в исходном HTML — ориентир по функциям. Отсутствие токенов FA или Cloudflare Access не является блокером проекта. Не просить эти токены и не восстанавливать автоматическое переключение на FA.

## Что уже исправлено в этой доработке

- Клиент FA (`fa-client.js`) и все маршруты FA удалены (31.10, PR #27 и #37): платформа работает только на своих сервисах, прежние ключи FA в окружении ни на что не влияют.
- `src/services/engine.js`: всегда `own`. Из запуска сервера убран воркер опроса FA. Существующие данные не удаляются.
- `src/api/routes/creatives.js`: создание и повтор используют собственный HTML/Playwright-движок, в том числе для ранее импортированного товара. Повтор сохраняет исходные цену, характеристики и референс, проверяет права. Ошибки отображаются как ошибки, а не как ожидание картинки FA.
- `src/services/creative-plan.js`: количество 1–10 проверяется; 8 означает восемь записей и попыток рендера. После пяти стилей цикл повторяется, поэтому восемь картинок не означают восемь уникальных композиций. Список интерфейса согласован с ограничением.
- `creative-generator.js`: исправлены размеры тела макета, добавлены 3:2 и 2:3; миниатюра уменьшается из готового изображения вместо обрезки заново открытого макета.
- Убраны кнопки и периодический опрос готовых картинок FA, синхронизация лендингов FA. В форме прямо указаны ограничения текущего собственного генератора.
- `/api/push/:id/trace` читает собственный журнал залива и проверяет команду/автора. Для него больше не нужен FA.
- Остальные старые маршруты FA возвращают явное сообщение об отключённой функции. Это **не реализация их собственного аналога**. Основные маршруты `/campaigns/fb/...`, Keitaro, своя витрина и агент сохранены.

Пути выше относительно `platform/backend`, кроме упоминаний интерфейса в `platform/frontend/src/pages/Creatives.jsx` и `Landings.jsx`.

## Объективные ошибки и реальные пробелы

1. **Архитектура расходилась с требованием.** Own выбирался лишь при отсутствии FA-токена, а в creative retry собственный товар получал ошибку «Товар не связан с FA». Исправлено. Требование без FA должно проверяться с намеренно установленными старыми ключами.
2. **Роудмап принимал распознавание URL за поддержку магазина.** Own принимает в работу только Amazon. Walmart, Target, Best Buy и Etsy требуют отдельных собственных адаптеров. Наличие parseProductLink ещё не означает скрапинг.
3. **Обещания формы опережают реализацию.** Локальный генератор — сборка изображения из фото и пяти HTML-стилей. Это не генеративный AI: идея, логотип и выбранный лендинг пока не используются, diversify отдельно не учитывается. Референсы используются как исходные картинки, не как анализ композиции. Нужно реализовать параметры или убрать неработающие элементы; не выдавать это за готовый AI.
4. **Количество и форматы были неверными.** При 8–20 выбранных картинках создавалось максимум пять; 3:2/2:3 превращались в квадрат; миниатюра обрезалась. Исправлено и проверено отдельно.
5. **Результат скрапа и рендера ждёт незавершённых обещаний в памяти процесса.** Перезапуск backend может оставить processing, а готовый результат агента не будет применён автоматически. Нужны сохраняемая связь product↔job, обработчик результата, таймаут и восстановление после рестарта. Отключённый FA-воркер этого не заменяет. Старые FA processing-записи также потребуют явной обработки: пометить для собственного повтора, не удаляя готовые данные.
6. **В текущем API список креативов ограничен командой, но не автором для buyer.** Генерация и повтор в этой доработке проверяют товар/автора, однако проверку всех списков и связанных объектов нужно закончить отдельно. Не считать весь старый аудит автоматически применённым.
7. **Документация расходилась с текущими файлами.** Старый README обещал seed, npm test, /ready и localhost, которых текущий исходный коммит в описанном виде не предоставлял. Нужна отдельная проверка чистой установки и локального режима, миграций с нуля и запуска из lock-файлов. Старые утверждения о нуле уязвимостей не заменяют аудит текущих lock-файлов; offline npm ci не является свежей проверкой реестра.

Эти выводы относятся к коду, а не к способностям Claude. Моя прежняя рекомендация получать доступ FA тоже была ошибкой относительно требования владельца.

## Порядок завершения

1. Закрыть права buyer на чтение, сохранение и связанные сущности; проверить на двух пользователях одной команды и на двух командах.
2. Сделать один устойчивый собственный маршрут Amazon: ссылка → задание конкретному профилю AdsPower → реальные данные → свои сохранённые фото → повтор без дублей после рестарта. CAPTCHA показывать как причину остановки, не имитировать успех.
3. Довести шаблонные креативы: реальные фото обязательны для результата, понятная причина отказа загрузки, логотип/идея реализованы или недоступны в форме, независимые задания и восстановление. Если нужен отдельный AI-движок — согласовать способ исполнения; он не должен зависеть от FA.
4. Добавлять прочие магазины по одному с фикстурами и тестами: цена/валюта/заголовок/галерея, варианты и недоступный товар. До появления адаптера говорить «не поддерживается».
5. Пройти свой лендинг и заказ до получателя. Проверять реальные переходы и события, не создавать фиктивный Purchase при одном нажатии кнопки.
6. Проверить Keitaro и свой FB-агент в тестовой среде. Повтор запроса/рестарт должны исключать обычные дубли; потерю ответа после создания сверять с кабинетом. Проверить состав, отдельные ставки, макросы и бюджеты.
7. Один живой залив создавать только после выбора владельцем кабинета, страницы, пикселя, гео, бюджета и ставки, **на PAUSED**. Изменения на рабочем сервере и такой залив в этой доработке не выполнялись.

## Проверки этой доработки

Из корня проекта после установки зависимостей обеих частей:

```sh
node --test platform/backend/test/standalone.test.js
npm run build --prefix platform/frontend
node platform/backend/test/standalone-browser.mjs
node platform/frontend/test/standalone-smoke.mjs
```

Для браузерных проверок нужен Chromium Playwright (`npx playwright install chromium` из backend). Новые тесты не используют рабочую базу. Шесть автоматических проверок выполняются с подменённым хранилищем/браузерным транспортом; отдельно реальный Chromium проверяет изображение и миниатюру трёх форматов. Проверка интерфейса использует временный локальный сервер и тестовые ответы API, контролирует отсутствие запросов FA и ошибок браузера.

Сборка проверена с точными версиями текущего frontend lock-файла (Vite 5.4.21 на момент записи; сейчас в frontend Vite 8). Есть предупреждение о крупном JS-файле, сборка проходит. Полный запуск backend, новая PostgreSQL-установка, реальные Amazon/Keitaro/Facebook и рабочий VPS этими тестами не подтверждены.
