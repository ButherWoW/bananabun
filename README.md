# Bananabun

Платформа управления товарами, креативами, лендингами и рекламными кампаниями. Сервер: Fastify/PostgreSQL, интерфейс: React/Vite, агент на Mac: AdsPower/CDP.

## Состояние

Актуальный план — [docs/roadmap.html](docs/roadmap.html). Объективный разбор исходной реализации и проверенных исправлений — [docs/REVIEW.md](docs/REVIEW.md).

Наличие кода и прохождение локальных тестов не означают, что внешние сервисы подключены. На проверенном VPS FA ответил 401; сервисные ключи Cloudflare Access отсутствуют. AdsPower на Mac отвечает и содержит 11 профилей; в момент проверки открытых профилей не было.

## Локальный запуск

Нужны Node.js 22.12+ и PostgreSQL 16. Команды выполняются из соответствующих каталогов проекта.

1. В `platform/backend` выполнить `npm ci`, скопировать `.env.example` в `.env`, указать адрес своей базы и случайный `JWT_SECRET` длиной минимум 32 символа. Пример в файле намеренно не подходит для запуска.
2. Выполнить `npm run db:migrate`. База создаётся миграциями с нуля, повторный запуск безопасен. Саму PostgreSQL-базу предварительно создаёт её администратор.
3. Только для совершенно новой установки указать в `.env` `OWNER_EMAIL`, `OWNER_PASSWORD`, `OWNER_NAME` и выполнить `npm run db:seed`. Уже существующая установка не перезаписывается. После создания удалить `OWNER_PASSWORD` из `.env`.
4. Выполнить `npx playwright install chromium`, затем `npm run dev` в backend.
5. В `platform/frontend` выполнить `npm ci`, затем `npm run dev`. Открыть `http://127.0.0.1:3000`.

По умолчанию сервер и интерфейс слушают только 127.0.0.1. Это ограничивает доступ к запущенному сайту; синхронизацию чата Codex эта настройка не меняет. Агента при разработке не запускать против рабочего сервера, если нужно работать только с тестовой средой.

Для Docker Compose: скопировать `platform/.env.example` в `platform/.env`, задать независимые случайные `DB_PASSWORD` и `JWT_SECRET`, выполнить `docker compose up --build` из `platform`. Все опубликованные порты привязаны к 127.0.0.1. Первого владельца создать отдельно командой `db:seed`, передав необходимые переменные в контейнер backend.

## Доступы FA

В окружении **сервера**, а не в коде браузера, нужны:

- `FA_AGENT_TOKEN`: действующий секретный токен, проверенный подключением MCP. Идентификатор агента не заменяет секрет.
- `FA_WORKSPACE_ID` (или прежний `FA_WORKSPACE`): нужная команда FA.
- `CF_ACCESS_CLIENT_ID` и `CF_ACCESS_CLIENT_SECRET`: сервисная пара Cloudflare Access для картинок.

После изменения окружения сервер перезапускается. В «Настройки → FA и картинки» можно посмотреть отсутствующие параметры и проверить связь. Проверка вызывает только подключение и список инструментов; платную генерацию и скрап она не запускает.

У существующего FA-товара кнопка «Обновить фото из FA без нового скрапа» повторно загружает изображения, не создавая новый платный скрап. У креатива с уже готовой генерацией повтор сначала пробует скачать её результат. Локальные креативы можно повторять без FA.

## Агент Mac

Агент запускается из `mac-agent/bananabun_agent.js`. Он использует Node.js 22+, локальный AdsPower и секретные файлы с правами 600. Каталог данных по умолчанию — каталог агента; при существующей установке в `~/scripts` можно задать `BANANABUN_AGENT_HOME=.../scripts` или явно `ADSPOWER_KEY_FILE` и `BANANABUN_AGENT_KEY_FILE`.

Для тестовой установки указать `BANANABUN_URL` тестового backend. Не переносить рабочие токены в Git. Состояние залива сохраняется в `push/<push_id>/state.json`; каталог и файлы не входят в репозиторий. Состояние записывается атомарно.

Все создаваемые Facebook-объекты имеют статус PAUSED. Включение — отдельное действие с подтверждением. Для первого живого теста нужны выбранные кабинет, страница, пиксель, гео, креативы, лендинг/вайт/офферы/домен Keitaro и согласованные бюджет и ставка.

## Проверки

Из `platform/backend`:

```sh
npm test
```

Без базы выполняются модульные проверки; интеграционные явно отмечаются как пропущенные. Для полного запуска создать **отдельную пустую тестовую базу**, имя которой заканчивается на `_test`, и выполнить:

```sh
DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:PORT/bananabun_test RUN_BROWSER_TESTS=1 npm test
```

Интеграционные тесты очищают данные только в переданной тестовой базе. Никогда не указывать рабочую базу.

Из `platform/frontend` после установки зависимостей обеих частей:

```sh
npm run build
npm run test:ui
```

Проверка интерфейса работает на локальном временном сервере с тестовыми ответами API. Снимки сохраняются в `docs/screenshots`. Это проверка отображения и переходов, а не подтверждение работы внешних интеграций.

## Выкатка

`platform/ship.sh` предназначен для уже настроенного VPS. Перед изменениями он делает копию исходников и дамп базы, передаёт исходники, зависимости и публичные файлы, применяет миграции и проверяет `/ready`. На VPS требуется Node.js 22.12+. Секреты `.env` и загруженные файлы не перезаписываются. Локальный агент обновляется отдельно и с сохранением его секретов и состояния.

Скрипты развёртывания подготовлены, но новая версия в рамках этой доработки на рабочий VPS не выкатывалась. Обновления миграций и версий зависимостей сначала проверяются на копии рабочих данных.
