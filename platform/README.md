# Локальный запуск Bananabun

Нужны Node.js 20+ и Docker Desktop. Этот порядок предназначен для **новой локальной копии** проекта. Если настройки уже существуют, подготовщик откажется их перезаписывать. Рабочая установка обновляется отдельно через согласованную выкатку Claude.

## Самый короткий путь

Из корня проекта:

```sh
node platform/setup-local.mjs
cd platform
docker compose up --build -d
docker compose run --rm backend sh -c 'npm run db:migrate && npm run db:seed'
```

Последняя команда попросит email и пароль первого владельца. Пароль не отображается; нужно минимум 12 символов и максимум 72 байта. Уже существующая установка и её пароли не перезаписываются. Никакой общий пароль по умолчанию не создаётся.

Открыть [http://127.0.0.1:3000](http://127.0.0.1:3000) и войти с созданными данными. PostgreSQL, сервер и интерфейс опубликованы только на 127.0.0.1; с другого устройства эти адреса недоступны. Созданные `.env` закрыты правами 600 и исключены из Git. Не пересылайте их вместе с исходниками.

Запуск сервера сам применяет миграции. На пустой базе сначала создаются основные таблицы. Повторный запуск пропускает уже применённые изменения. Ошибочная миграция откатывается целиком; два одновременных запуска не применяют один файл дважды.

Установка Docker включает Chromium для собственных креативов. Для Amazon/Walmart и работы с рекламным кабинетом дополнительно нужен агент AdsPower; сам локальный запуск не подключает и не перенастраивает рабочий агент. FA не требуется.

## Остановка и повторный запуск

Из `platform`:

```sh
docker compose stop
docker compose start
```

База хранится в томе Docker и сохраняется при остановке. `docker compose down` тоже сохраняет её. **Не добавляйте `--volumes` к остановке своей установки**, если хотите сохранить товары и пользователей.

Если порт занят, в `platform/.env` можно задать `BACKEND_PORT` и `FRONTEND_PORT`. Порт базы задаётся `LOCAL_DB_PORT` (по умолчанию 54329). При изменении порта интерфейса открывайте соответствующий адрес 127.0.0.1. Для работы Node.js вне Docker также обновите соответствующие адреса в локальных настройках.

## Разработка без контейнеров приложений

Сначала выполнить подготовку настроек, затем из `platform` запустить только базу:

```sh
docker compose up -d postgres
```

В первом терминале, из `platform/backend`:

```sh
npm ci
npx playwright install chromium
npm run db:migrate
npm run db:seed
npm run dev
```

Во втором терминале, из `platform/frontend`:

```sh
npm ci
npm run dev
```

Сервер и dev-интерфейс используют localhost из созданных настроек. Для внешних подключений требуется отдельная явная настройка.

## Проверки

После установки зависимостей обеих частей и Chromium, из `platform/backend`:

```sh
npm test
```

Проверки PostgreSQL без явно заданной тестовой базы отмечаются как пропущенные. Для полного прогона нужна **отдельная локальная база**, имя которой заканчивается на `_test`:

```sh
BANANABUN_TEST_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:PORT/bananabun_test RUN_BROWSER_TESTS=1 npm test
```

Не указывайте основную базу установки. Тесты создают отдельные временные схемы и удаляют только их. Из `platform/frontend` команда `npm test` собирает интерфейс и запускает браузерные проверки на тестовых ответах API.

Скрипт `src/db/seed.js` также принимает `OWNER_EMAIL`, `OWNER_PASSWORD`, `OWNER_NAME`, `WORKSPACE_NAME` из окружения для автоматического развёртывания. После создания владельца удалите `OWNER_PASSWORD` из окружения. Пароли и хеши в отчёт не выводятся.
